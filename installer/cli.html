Meerya Rev.C command line flasher

Clone the installer repository, verify the published firmware bundle, flash it with esptool, then reboot the ESP32-S3 out of ROM download mode.

Browser installer Installer repository Firmware source

1. Clone the installer and prepare esptool

Python 3 and Git are required. esptool 4.9 or newer provides the ESP32-S3 watchdog reset used below.

git clone https://github.com/Syzygyx/meerya-esp32-installer.git
cd meerya-esp32-installer/installer
python3 -m venv .venv
# macOS / Linux
source .venv/bin/activate
python -m pip install --upgrade pip "esptool>=4.9"
python -m esptool version

On Windows PowerShell, activate the environment with .\.venv\Scripts\Activate.ps1 instead of the source command.

# Windows PowerShell, from meerya-esp32-installer\installer
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip "esptool>=4.9"
python -m esptool version

2. Enter ROM download mode

  1. Connect the Meerya Rev.C over USB and locate its ESP32-S3 serial port.
  2. Hold BOOT low, pull EN low, release EN while keeping BOOT low, wait for the ROM USB serial device to appear, then release BOOT.
  3. List available ports and set PORT to the ROM port.
# macOS
ls /dev/cu.usbmodem*
export PORT=/dev/cu.usbmodem1101

# Linux
ls /dev/ttyACM* /dev/ttyUSB*
export PORT=/dev/ttyACM0

# Windows PowerShell: replace COM7 with the port shown in Device Manager
$env:PORT = "COM7"

First install: use the physical BOOT and EN sequence. BLE can request bootloader mode only when the currently running firmware already has BLE control.

3. Verify and flash the Rev.C bundle

Run these commands from meerya-esp32-installer/installer. The checksums ensure the downloaded images match the installer manifest before writing flash.

python -c "import hashlib,json,pathlib; r=pathlib.Path('.'); m=json.loads((r/'firmware/manifest.json').read_text()); t=next(x for x in m['targets'] if x['id']=='meerya-revc-uac'); assert all(len((p:=r/f['path']).read_bytes())==f['size'] and hashlib.sha256(p).hexdigest()==f['sha256'] for f in t['files']); print('Bundle verified:',t['name'])"

python -m esptool --chip esp32s3 --port "$PORT" \
  --before no-reset --after no-reset write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x0 firmware/meerya-revc-uac/bootloader.bin \
  0x8000 firmware/meerya-revc-uac/partition-table.bin \
  0xe000 firmware/meerya-revc-uac/ota_data_initial.bin \
  0x20000 firmware/meerya-revc-uac/meerya_esp32.bin

For Windows PowerShell, use $env:PORT and run the multiline command with backticks:

python -m esptool --chip esp32s3 --port $env:PORT `
  --before no-reset --after no-reset write-flash `
  --flash-mode dio --flash-freq 80m --flash-size 16MB `
  0x0 firmware/meerya-revc-uac/bootloader.bin `
  0x8000 firmware/meerya-revc-uac/partition-table.bin `
  0xe000 firmware/meerya-revc-uac/ota_data_initial.bin `
  0x20000 firmware/meerya-revc-uac/meerya_esp32.bin

python -m esptool --chip esp32s3 --port $env:PORT `
  --before no-reset --after no-reset write-mem 0x6000812c 0 0x1
python -m esptool --chip esp32s3 --port $env:PORT `
  --before no-reset --after watchdog-reset run

4. Start the app with watchdog reset

ESP32-S3 USB Serial/JTAG may remain in ROM after a regular USB reset because it does not resample the BOOT strap. Clear the force-download bit, then use esptool's watchdog reset to reboot into the flashed app.

python -m esptool --chip esp32s3 --port "$PORT" \
  --before no-reset --after no-reset write-mem 0x6000812c 0 0x1

python -m esptool --chip esp32s3 --port "$PORT" \
  --before no-reset --after watchdog-reset run

After the USB device reconnects, confirm that the app interface enumerates. The Rev.C target uses USB VID 0x303A and PID 0x8007. If it still appears as ROM USB Serial/JTAG, check that BOOT is released and pulse EN once.

This page flashes the development-lab Rev.C bundle published with the installer. It is not the signed production provisioning workflow.
