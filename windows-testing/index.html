Meerya Windows Audio Validation

Public methodology and results for Windows microphone, speaker, duplex, and Google Meet compatibility testing.

Published test packet

Current Assessment

The current public installer build enumerates on Windows as Meerya UAC1 48k Mono. Windows native microphone capture, Chrome/WebRTC capture, and the WebRTC path from the meet.google.com origin all captured 48 kHz mono audio with no clipping. Browser duplex tests showed Meerya receiving the computer-side stimulus while suppressing its own speaker stimulus.

The actual Google Meet meeting-room UI was not fully automated because the fresh Chrome profile reached Google sign-in. The relevant customer risk path was still exercised directly from the Google Meet origin with Google Meet-style getUserMedia constraints.

Google Meet Methodology And Results

Method

Chrome was launched on WinBook and granted microphone permission. The probe selected the explicit Meerya audio input device, then called navigator.mediaDevices.getUserMedia with constraints matching the Google Meet capture path. 

{
  echoCancellation: true,
  noiseSuppression: true,
  autoGainControl: true,
  sampleRate: { ideal: 48000 },
  sampleSize: { ideal: 16 },
  channelCount: { ideal: 1 }
}

Duplex And Speaker Methodology

The public installer web test selects the computer speaker as computer output, Meerya as USB input/output, emits a broadband chirp from the computer, emits a different continuous noise stimulus from Meerya, records Meerya, and checks that the Meerya microphone matches the computer stimulus while suppressing the Meerya speaker stimulus.
